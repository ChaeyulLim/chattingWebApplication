# 학습 기술 목록

> 기간: 2026-09-17 ~ 2026-09-21
> 새로 알게 된 기술/개념을 분류별로 기록한다. (표시: 사용 = 프로젝트에 적용, 개념 = 이해만 함, 미도입)

---

## 1. 개발 환경 / 도구
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| uv | pip + venv + pyenv 역할을 합친 Rust 기반 도구. `python -m uv`로도 실행 가능 | 사용 |
| uv python install / uv venv | 시스템 Python과 별개로 원하는 버전(3.12)을 설치하고 가상환경 생성 | 사용 |
| venv 활성화 | 활성화한 상태에서는 `uv run` 없이 `flask`, `python`을 바로 실행 | 사용 |
| python-dotenv / `.env` | 비밀 값과 설정(DB 주소, SECRET_KEY)을 코드 밖에서 관리 | 사용 |
| DB Browser for SQLite | `chat.db`를 GUI로 열어서 테이블과 데이터 확인 | 사용 |

## 2. Flask 기본
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| `@app.route` / `methods` | 주소와 함수 연결, 같은 주소에서 GET(화면)/POST(데이터) 분리 | 사용 |
| `render_template` | `templates/` 폴더의 HTML을 렌더링, 값을 넘겨서 전달 | 사용 |
| Jinja2 템플릿 문법 | `{{ 값 }}` 출력, `{% if %}` 조건문, `\|tojson` 필터 | 사용 |
| `request.form` | form으로 전송된 값을 `name` 기준으로 꺼냄 | 사용 |
| `redirect` | 처리 후 다른 주소로 이동시킴 (POST 후 redirect = PRG 패턴) | 사용 |
| `session` | 서명된 쿠키에 로그인 정보 저장 (`get`/`pop`) | 사용 |
| `app.config` | 앱 설정 (`SECRET_KEY`, `SQLALCHEMY_DATABASE_URI`) | 사용 |
| `app.json.ensure_ascii` | JSON 응답에서 한글이 `\uXXXX`로 나오는 원인과 설정법 | 개념 |
| `login_required` 데코레이터 | 로그인 필수 페이지를 한 줄로 만드는 방법 (`functools.wraps`) | 미도입 |
| `flash()` | redirect 이후에도 한 번 전달되는 메시지 | 미도입 |
| `url_for()` | 주소 대신 함수 이름으로 경로 지정 | 미도입 |

## 3. Flask 확장 라이브러리
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| Flask-SQLAlchemy | SQLAlchemy(ORM)를 Flask에 연결. Flask 내장이 아니라 별도 설치 | 사용 |
| Flask-Migrate (Alembic) | 스키마 변경을 데이터 손실 없이 반영. `init` / `migrate` / `upgrade` | 사용 |
| Flask-SocketIO | WebSocket 위에 이벤트, 방(room) 기능을 얹은 라이브러리 | 사용 |

## 4. DB / ORM
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| ORM | SQL 대신 파이썬 객체로 DB를 다룸. DBMS가 바뀌어도 코드 유지 | 사용 |
| SQLite | 서버 없이 파일 하나가 DB. 개발/테스트용 | 사용 |
| DB 접속 주소 형식 | `종류://서버/경로` (SQLite는 슬래시 3개), 상대경로는 실행 위치에 영향받음 | 사용 |
| 모델 컬럼 타입 | `String`, `CHAR`, `Integer`, `Date`, `DateTime` 등 엑셀 타입과의 대응 | 사용 |
| PK / FK / UNIQUE / nullable | 기본키, 외래키(원본 테이블 참조), 중복 방지, NULL 허용 여부 | 사용 |
| 정규화 | 같은 정보를 중복 저장하지 않고 id(FK)로 참조 | 개념 |
| 연결 테이블 (다대다) | n:n 관계를 중간 테이블(`ROOM_MEMBER`)로 표현 | 사용 |
| surrogate key | 의미 없이 행을 구분하는 자동증가 일련번호 (복합키와 비교) | 사용 |
| 소프트 삭제 (nullable date) | NULL이면 가입 중, 날짜가 있으면 탈퇴 | 사용 |
| `db.session.add` / `commit` | 저장 대기열에 올린 뒤 `commit`에서 실제 INSERT | 사용 |
| `query.filter_by` / `first` / `all` | 조건 조회, 1개(`None` 가능)/전체(리스트) | 사용 |
| `query.filter` + `in_` / `or_` / `is_` | `=` 이외 조건, IN, OR, NULL 비교 | 개념 |
| `order_by` / `count` / `db.session.get` | 정렬, 개수, PK 조회 | 개념 |
| 조건식의 원리 (연산자 오버로딩) | `UserInfo.UI_ID == "a"`는 True/False가 아니라 SQL 조건 조각 | 개념 |
| 서브쿼리 | 다른 테이블 조회 결과를 `IN`에 넣는 방식 (내가 참여한 방 목록) | 개념 |
| 직접 SQL (`text()`) | 값은 `:이름` 바인딩으로 전달 | 개념 |
| SQLite와 PostgreSQL 차이 | VARCHAR 길이 미강제, FK 미검사 | 개념 |

## 5. 웹 / 네트워크
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| HTTP 무상태 | 요청마다 상대를 기억하지 못하는 구조 | 개념 |
| 쿠키 | 서버가 `Set-Cookie`로 내려주면 브라우저가 저장하고 요청마다 자동 전송 | 사용 |
| GET / POST | GET은 주소창에 값 노출, POST는 본문으로 전송 | 사용 |
| 302 redirect / PRG 패턴 | POST 후 새로고침 시 재전송 방지 | 사용 |
| WebSocket | HTTP 핸드셰이크(`101`) 후 연결을 유지, 서버가 먼저 전송 가능 | 사용 |
| Socket.IO 이벤트 | 클라이언트 `emit` ↔ 서버 `@socketio.on`, 이벤트 이름 일치 필수 | 사용 |
| 실시간 방식 비교 | 폴링, SSE, WebSocket, WebRTC의 방향성과 용도 차이 | 개념 |
| Socket.IO room | `join_room` + 방 단위 `emit`으로 채팅방 구현 | 미도입 |
| CDN | 외부 라이브러리를 `<script src>`로 불러옴 (로드와 연결은 별개) | 사용 |

## 6. 보안
| 기술 | 알게 된 내용 | 상태 |
|---|---|---|
| 비밀번호 해시 | `generate_password_hash`로 저장, `check_password_hash`로 검증 (`==` 불가) | 사용 |
| SECRET_KEY | 세션 서명용 비밀 문자열 (SSL 인증서와는 다른 개념) | 사용 |
| 서버 검증 vs HTML 검증 | `required`는 편의 기능, 서버 검증이 실제 방어선 | 사용 |
| 로그인 실패 메시지 통일 | 아이디 존재 여부를 알려주지 않기 위해 | 개념 |
| SQL 인젝션 | 값을 문자열로 SQL에 끼우면 위험, 바인딩으로 방지 | 개념 |
| XSS | 스크립트에 값을 넣을 때 `\|tojson`으로 이스케이프 | 개념 |
| 개발용 조회 주소 노출 | `/userInfo`는 배포 전 제거 필요 | 개념 |
