# 개발 일지

## 2026-09-17
### 금일 목표
 - Web 화면을 통해 Client 2개가 같은 서버로의 데이터를 받아들이는 기능 제작.
   - 채팅의 기본기

### 진행 내용
 - SocketIo 라는 라이브러리를 통해 HTTP가 Server 와 실시간 통신할 수 있도록 설정
 - 디렉토리 구조
    ├──┬ templates
    │  └─ index.html
    └─── app.py
 - 프로젝트 정의: Python Flask API 기반 백엔드 포트폴리오, 카카오톡 컨셉(1:1, 그룹, 오픈채팅)
 - DB는 개발 단계에서 SQLite, 배포 단계에서 PostgreSQL 로 전환
 - 협업 규칙(소통.md) 확인: 검증된 기술만 사용, 모르는 기술은 도입하지 않음
 - 라이브러리 선정: Flask, python-dotenv, Flask-SQLAlchemy(ORM), Flask-Migrate, Flask-SocketIO
 - uv 로 Python 3.12 가상환경(.venv) 구성
 - WebSocket 학습: HTTP 는 요청해야 응답하지만, WebSocket 은 연결을 유지하며 서버가 먼저 전송 가능
 - 채팅 구조 결정: 유저별 주소(/user1) 대신 방(Room) 중심 모델, DB(기록/권한) + WebSocket(실시간) 두 축으로 동작
 - 개발 순서: 모델링 → 인증 → REST API → 실시간 → 프론트 → 부가기능 → 테스트 → 배포

### 이슈 / 해결

### 진행 내용
 - DB 쿼리 TYPE 설정
 - USER_INFO, ROOM_INFO, ROOM_MEMBER, CHAT_MESSAGE
 - 러프한 모델로 시작하고 Flask-Migrate 로 스키마를 다듬는 방식으로 결정
 - 정규화: 같은 정보를 중복 저장하지 않고 원본 테이블의 id(FK)로 참조, 다대다(n:n)는 연결 테이블(ROOM_MEMBER)로 해결
 - 설계 결정
   - 비밀번호는 해시로 저장 (해시가 길어서 VARCHAR 255)
   - 탈퇴 여부는 날짜 한 컬럼에 NULL 허용 (NULL=가입 중, 날짜=탈퇴일)
   - RI_ID 는 INT 자동증가 (010291 같은 앞자리 0은 화면에서 포맷)
   - 방 종류 컬럼으로 1:1 / 그룹 / 오픈 구분
   - CM_DATE 는 시각까지 저장하는 DATETIME
 - 방장/권한, 참여일자는 나중 기능으로 미룸

### 이슈 / 해결
 - UI_DDATE 이름과 용도 불일치 / UI_WITHDRAWN(DATE, NULL)로 통합
 - ROOM_INFO 에 참여자 ID 를 넣은 구조 / ROOM_MEMBER 연결 테이블로 분리
 - CM_DATE 가 DATE 타입 / 시각 순서가 필요하므로 DATETIME 으로 변경
 - 방 종류에 1:1 값이 없음 / Group, Dm 으로 변경
